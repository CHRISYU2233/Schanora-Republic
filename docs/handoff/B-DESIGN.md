# 设计规范落地说明（B）

> 2026-11-13 · 参考 [`VoltAgent/awesome-design-md`](https://github.com/VoltAgent/awesome-design-md)
> 的 Stitch DESIGN.md 格式与 Spotify 那份的具体规则
> 产出：`DESIGN.md`（根）、`design/preview*.html`、`scripts/check-design.mjs`

## 一、为什么不是"再美化一轮"就完事

上一轮（v3）把**新写的**部分按 Spotify 规范做对了，但老规则还在底下生效。扫一遍代码就能看到：

| 项 | 规范声称 | 代码实际（对齐前） |
|---|---|---|
| 字重 | 700 / 600 / 400 | 还有 **500、640、650** 三档 |
| 圆角 | 4 / 6 / 8 / 12 / 999 | 还有 **3px、10px** |
| 字号 | 6 档 | **14 档**（9.5–21，其中 6 档只差 0.5px） |
| 颜色 | 全部走 token | **36 个裸 hex**、**29 处裸 rgba** |
| 深色 | 一套覆盖 | **两套 `body[data-ds-dark-theme]` 互相覆盖**，后写的赢，没人知道哪套在生效 |

所以这轮的目标不是"更好看"，而是**把规范变成会失败的门槛**：文档、代码、校验三件套。

## 二、采纳了什么（附理由）

| 参考里的做法 | 采纳 | 为什么 |
|---|---|---|
| YAML front matter 存 token（colors / typography / rounded / spacing） | ✅ | 这是"agent 可读"的关键：结构化的值能被比对，散文不能 |
| 每节先给表、再给原则 | ✅ | 表给值，原则给判断；只有表会照抄，只有原则会跑偏 |
| 颜色必须带"用在哪"的角色说明 | ✅ | 我们的旧规范只有色值，没角色，才会出现同一个灰用在三处不同层级 |
| surface 阶梯（canvas → surface-1 → surface-2）代替描边分层 | ✅ | 直接对上本项目"卡片不描边"的既有决策 |
| Do's and Don'ts 用反模式写 | ✅ | 「不要 500 字重」比「字重应保持克制」可执行 |
| Iteration Guide（改的时候按什么顺序想） | ✅ | 减少下次改动从"我觉得"开始 |
| Known Gaps（诚实列出没验证的） | ✅ | 和本项目"不把未验证写成通过"的口径一致 |
| `preview.html` / `preview-dark.html` 可视目录 | ✅（脚本生成） | 唯一能"一眼验收 token"的东西；手写会变成第二套真相，所以从 `ui.js` 直接抠 CSS 生成 |
| 品牌专属字体（Linear Display 等） | ❌ | 插件跑在别人壳里，加载字体等于制造 FOUT；跟随宿主字体栈 |
| 80px 级 display 字阶 | ❌ | 这是应用界面不是营销页，最大 21px |
| 大幅装饰性渐变 / 玻璃拟态 | ❌ | 与"密集知识工作台"的场景相悖 |
| 语义 token 用 `{colors.primary}` 引用语法 | ⚠️ 部分 | 文档里用人话描述（"品牌绿只给可点元素"），代码里用 CSS 变量；不引入额外模板语法 |

**一处刻意偏差**：Spotify 规定绿色不用于背景，但 Schanora 的品牌带必须整条 `#00642F` 绿底白字
（字标原图底色就是它，换底色接缝可见）。已写进 `DESIGN.md` §8，避免后来人当 bug 修。

## 三、落地后代码里到底改了什么

1. **token 收敛为唯一来源**：`.sch-tokens` 定义全部键（含阴影），深色只覆盖要变的 26 个键；
   删掉了 v3 里重复定义 `--sch-radius/--sch-shadow` 的第二个 `.sch-tokens` 块和第二个深色块。
   新增 `--sch-on-green` / `--sch-brand-green-2` / `--sch-brand-edge` / `--sch-plate` /
   `--sch-scrim` / `--sch-focus-ring` / `--sch-gloss` / `--sch-gloss-strong` 八个键，
   把原先散在规则里的 8 处 `#fff`、`#00552A`、rgba 阴影与遮罩收进去。
2. **字阶从 14 档收到 9 档**：`9.5→10`、`11.5→11`、`12.5→12`、`14.5→14`、`20→21`。
3. **字重只留 400/600/700**：`650/640→700`，`500→600`。
4. **圆角只留 4/6/8/12/999**：`3px→4px`（徽标/序号/内联代码）、`10px→12px`（弹层/textarea）。
5. **深色底色修正**：`#16181C → #121212`（此前比 `layer` 还亮，README 写的 `#121212` 其实没生效）。
6. **v4 走查四项**：次级按钮描边从 8% 提到 14%（"停止"原来像裸文字）、
   助手气泡限宽 72ch、问答滚动区上下 14px 淡出（气泡不再被硬边切一半）、表格"操作"列表头右对齐。

**没有改动任何交互、数据流与文案。**

## 四、怎么验证

```bash
npm run check        # bundle 自检 + 设计校验（裸色值 / 字重 / 圆角 / 字号 / 死 token / 文档漂移）
npm run design       # 重新生成 design/preview.html 与 preview-dark.html
npm run shots        # 32 张产品截图，控制台 0 错误
```

`check-design` 现在会拦下这些：

```
✗ 没有裸色值（一律走 token）        —— 有人写了 #FFF 而不是 var(--sch-on-green)
✗ 字重只有 400 / 600 / 700          —— 有人写了 550
✗ 圆角落在 4 / 6 / 8 / 12 / 999px   —— 有人写了 10px
✗ 字号落在 9 档字阶内               —— 有人写了 11.5px
✗ 没有定义未用的 token              —— 删了用法忘了删变量
✗ DESIGN.md 的色值都能在代码里找到  —— 文档写了代码里没有的颜色
```

例外只允许两种：token 定义行本身，以及行内 `design-ok: 理由` 注释（目前只有 mask 语法必须用 `#000` 这一处）。

## 五、仍然没做的

1. **对比度没做全量 WCAG 校验**：只保证"能读"，`--sch-text-3` 在浅色下约 3:1，仅用于元信息。
2. **动效时长未 token 化**：120–200ms 散在各处，`DESIGN.md` §11 已记为 Known Gap。
3. **`design/preview.html` 不含真实数据流**：它是 token 验收台，不是产品页；功能验收仍看 32 张产品截图。
4. **宿主换字体/换主题**（如高对比度）未适配，需要时在 `.sch-tokens` 补一组覆盖。

## 六、v5：结构层适配（去侧栏化）

前面五节都是"画得对不对"，这一节是"放不放得下"。用户在 DSH 里截图反馈问答区太小，
量出来是 280（DSH 侧栏）+ 242（面板侧栏）+ 212（会话列）三层竖栏，消息区只剩 570。

改法与结果写在 `docs/evidence/M4M5-B.md` 第八节。对设计系统本身的影响有三条：

1. **导航形态变了**：`.sch-navitem`（34px 竖排项）→ `.sch-tab`（30px 横向胶囊）。
   胶囊规则不变（999px、选中绿底白字），只是方向换了。
2. **品牌从"带"降为"块"**：76px 整条绿底 → 30px 方块。DESIGN.md §8 里那条
   "不要用绿色做背景"的例外，范围从"整条"改成"一枚方块"。
3. **新增一条 Don't**：不要在 `main` 槽里再画侧栏。这是宿主插件最容易犯的错——
   本地预览看起来像独立应用，进宿主就是"栏中栏"。

顺带删掉两个随之失效的 token（`--sch-side-bg`、`--sch-brand-green-2`），
`check-design.mjs` 的"未使用 token"检查就是靠这次发现的。




## 七、v6：明亮模式配色修正（暗色一字未改）

用户在宿主里截了张明亮态问答页：用户气泡和选中的会话项是**实心亮绿**，压在上面的字发虚。
这不是调错色，是**把宿主 token 当成了自己的语义**。

| | 值 | 来源 | 后果 |
|---|---|---|---|
| `--sch-green-tint` | `#4ED17E` | 宿主的 `--dsw-alias-state-success-secondary` | 一整块气泡铺上去就是荧光笔，深绿字压在上面只有 **3.98:1** |
| `--sch-text-3` | 宿主 `label-tertiary` | 宿主的 `label-tertiary` | 白底 **3.2:1**，时间戳、脚注发灰 |
| `--sch-layer` / `-2` | 宿主的 `bg-layer-1/2` | 宿主 | 与白底只差 1–2%，卡片在纯白上等于没有边 |

深色没出问题，是因为深色那块我们本来就本地覆盖了（`rgba(0,140,60,.16)`）——
这恰好说明：**依赖宿主 token 的地方，只在宿主改值时才暴露**。

改法：这四个键改为自持，不写 `var(--dsw-alias-*)`；深色覆盖一字未动。

| Token | 改前（宿主给） | 改后（自持） | 理由 |
|---|---|---|---|
| `--sch-green-tint` | `#4ED17E` | `#E8F3EC` | 品牌绿的 8% 提亮版，绿仍然是绿，但不再抢视线 |
| `--sch-text-3` | ≈`#8A948F`（3.2:1） | `#6C7671`（4.7:1） | 过 4.5 线，元信息才读得清 |
| `--sch-layer` | ≈`#F6F7F8`（1.03:1） | `#F1F3F1`（1.13:1） | 卡片在纯白底上要看得见边界 |
| `--sch-layer-2` | ≈`#EFF1F3` | `#E7EBE8` | 与一级面拉开一档，hover 才有反馈 |

顺带修的两处（都与配色无关，但同一张截图里看得出来）：

- **会话列表横向溢出**：`.sch-sesslist` 只写了 `overflow-y`，标题一长就冒出横滚条（截图里那条灰条）。补 `overflow-x: hidden`。
- **顶栏品牌**：手绘的矢量 S 换成真字标（`assets/schanora-wordmark-trim.png`，20px 高），导航改三轨 grid 居中。

对比度是算出来的，不是看出来的：`#00642F` on `#E8F3EC` = 7.2:1，`#17251E` on `#E8F3EC` = 13.4:1。

### 7.4 字标放大（v6.1）

宿主内看字标偏小：底板 30 → 38px、字形 20 → 26px（宽约 115px），仍然只占左侧轨道，三轨 grid 不变；<640px 回落 30px / 21px。改动只在 `.sch-top-brand` 与 `.sch-top-glyph` 两个类，不影响导航居中。

### 7.5 v7：输入区贴底 + 设置抽屉 + 插件中心

三处结构性改动，都是为了「宿主里能用」而不是「截图好看」：

| 问题 | 原因 | 改法 |
| --- | --- | --- |
| 输入框随页面滚动 | 宿主 main 槽没有确定高度，`.sch-panel{height:100%}` 解不出来，面板按内容长高，整页滚动 | `Panel` 量「面板顶边→最近可滚动祖先下沿」写成 `--sch-panel-h`；面板刚好等于可视区，滚动收进 `.sch-content` |
| 输入区跟着消息滚 | 问答页只有 `min-height:420px`，没有上限 | 模块注册加 `fit:true` → `.sch-modwrap.fit` 整块贴高，`.sch-chat` 撑满，`.sch-thread` 内部滚动，`.sch-composer` 常驻底部（再加 `sticky` 兜底） |
| 设置找不到 | 入口在 `⋯` 菜单里，内容挤在 360px 小弹层 | 顶栏常驻「设置」按钮 → 460px 抽屉，分连接 / 检索 / 本地插件三段 |

输入区尺寸：`min-height` 56 → 96px、`max-height` 132 → 240px、正文 12 → 14px、内距 8×10 → 12×14、`resize:vertical` → `none` + 按内容自动增高（1–6 行）。发送按钮 30 → 40px 高。理由：这是主输入面，56px 在 1080 窗口里只有两行，长问题要一路横滚。

顶栏三轨 grid 从 `1fr auto 1fr` 改成 `minmax(auto,1fr) minmax(0,auto) minmax(auto,1fr)`：原来两侧 `minmax(0,1fr)` 会缩到 0，而中轨是 `auto`（= max-content）不肯缩，900 / 800 宽度实测导航直接压到工具按钮上。改成两侧保底最小内容宽度、中轨可缩并横滚后，1080 仍然几何居中，800 只有导航自己横滚。另加：≤1000px 隐藏连接状态胶囊。

新增 token 一个：`--sch-shadow-up`（向上投影，给贴底输入区做分隔）。浅色 `rgba(10,20,15,.28)`、深色 `rgba(0,0,0,.55)`，避免在 CSS 里写裸色值。

## 八、v8：WeKnora 生态插件落地（P1 / P2 / P3 / P4）

本版按 2026-11-13 交接包新增三个页签，并对 P3 的范围规则做纠偏。设计判断如下：

| 决定 | 理由 | 代价 |
| --- | --- | --- |
| P1 用「行为重实现」而非源码移植 | 商店扩展源码与许可未核实；把 MIT 仓库许可推定为扩展许可不成立 | 需要自己维护去重/版本语义，已抽到 `src/lib/clip.js` 并写 18 条单测 |
| 去掉「全部知识库」 | 上游空范围=全库，会把范围结果伪装成全库结果（T01） | 用户多点一次选库；未选时给明确提示而不是静默全查 |
| 每次提问锁定范围快照 | 切库漂移会让答案与事后核对不一致（T02） | 气泡多一行元信息 |
| 普通问题只出证据，深度研究才合成 | 避免两轮不必要的模型回答；DSH 是业务入口，WeKnora 是知识引擎 | 面板内不再默认给出成段答案 |
| 浏览器页签只做协同与交接 | 不重写浏览器内核；官方插件是技术组件 | 真实采集依赖插件安装，未装时明确禁用 |
| 状态时间线用圆点+连线 | 候选有 9 个状态，进度条无法表达失败/取消分支 | 窄窗换行，已在 Known Gaps 标注 |

去重与版本：内容级幂等键 `库::URL::hash` 负责「同内容不建副本」，资料身份键 `库::URL`（笔记用标题）负责「内容变化形成同文档新版本」。两个键分开，是因为把 hash 放进身份键会让每次更新都变成新文档——这是实现过程中实际踩到并修掉的缺陷（截图 `36-clip-newversion.png` 前后对比）。

会话绑定：范围从「面板本地 state」改为「按 sessionId 读写 localStorage」，切会话重读；头部徽标经 `store.publishScope` 同步，避免顶栏显示「未选库」而面板已选库的不一致。

新增 token：无。复用 32 个既有 token（`--sch-plate` / `--sch-ok` / `--sch-green-2` / `--sch-layer-2` 等）。

## 九、v9：界面精简（低频收纳 + 间距收敛）

| 决定 | 理由 | 代价 |
| --- | --- | --- |
| 页签栏 9 → 7，Wiki / 插件中心收进 `⋯` 菜单 | 两者低频；9 枚页签让中轨拥挤、弱化了「可用功能」分组 | 多点一次菜单；当前模块在菜单里时 `⋯` 按钮呈绿色激活态，位置感不丢 |
| `⋯` 菜单删掉重复的「设置」项 | 常驻设置按钮就在它左边，菜单里再放一个属于同一入口画两遍 | 无 |
| pagehint 只留描述小字，删掉与选中页签重复的粗体标题 | 当前位置由页签栏（或 `⋯` 激活态）表达，再写一遍是纯噪声 | 窄窗整行隐藏 |
| 模块注册表加 `more: true` 白名单字段 | 收纳是声明式的：第三方模块注册时同样可选 | 注册表多一个布尔 |
| 布局间距收敛到 DESIGN.md 档位（14→16、18→16、22→20） | 手调值破坏纵向节奏；控件内部几何值不动 | 视觉位移 ≤2px |
| 插件卡片：脚注行与虚线上边框并入右上角开关 | 「纯前向执行…」每张卡重复一遍，分组说明已覆盖 | 卡片少一行 |
| 清死代码：9 个无引用 CSS 类（`.sch-ktr` / `.sch-cards` / `.sch-card` 族等） | 扫描确认 JS / harness / 截图脚本零引用 | 无 |

字典键不删：`t()` 存在大量动态取键（`t(mod.title)`、`t(\`wiki.status.${s}\`)` 等），静态扫描的「未引用」全是误报，删了会丢运行时文案。
