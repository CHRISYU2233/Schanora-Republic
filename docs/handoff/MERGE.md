## 二、布局决定：平铺，不建 `frontend/`

原本计划整包放进 `frontend/`（根 README 里 A、B 约定位置）。既然已经平铺上传且工作正常，
**就保持平铺**——理由：

1. 平铺后 `plugins/` `preview/` `scripts/` `brand/` `package.json` 与 `gateway/` 同级，语义清楚：
   前端是一等公民，不是塞在某个目录里的附件；
2. 所有文档里的相对链接（`docs/handoff/A-NEXT.md`、`docs/evidence/...`）都是按平铺写的，
   搬进 `frontend/` 反而要改十几处链接；
3. 再搬一次目录，GitHub 上会显示成「全删 + 全增」，历史更难读。

**不要**再改成 `frontend/`。

## 五、以后怎么判断会被覆盖

同一个相对路径就是「覆盖」。本包与仓库重名的只有根 `README.md` 和 `.gitignore` 两个，
其余全是新路径。判断方法：

```bash
# 在本包目录跑，输出就是会被覆盖的文件
comm -12 <(cd /path/to/Schanora && git ls-files | sort) \
         <(find . -type f -not -path "./.git/*" | sed 's|^\./||' | sort)
```

已知坑：

- **GitHub 网页上传不认隐藏文件**，所以 `.gitignore` 没被覆盖——这次是运气好，别指望下次；
  真要改它，手动编辑。
- **上传不会删文件**：目标目录里原有的、本次没上传的文件会保留（`docs/api.md` 就是这样活下来的）。
- **别把 `dist/` 一起传**：里面有整包副本 + zip，等于把仓库内容再存一遍。
