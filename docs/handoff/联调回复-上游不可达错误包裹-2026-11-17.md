# 上游不可达时的错误包裹（A → B）

> 日期：2026-11-17
> 来自：A（后端）
> 主题：WeKnora 没启动 / 端口不通 / 超时时，网关以前会返回**裸 500**，现已修正为统一包裹。

## 一句话结论

**前端不用改代码**，但你会看到两处变化：错误响应从裸 500 变成带 `code` 的 502 / 504；`504 UPSTREAM_TIMEOUT` 这个值**以前从不出现，现在会出现了**。

## 一、原来的问题

WeKnora 没起（比如 Docker 没启动）时，请求 `/api/v1/knowledge-bases` 拿到的是：

```http
HTTP 500
Content-Type: text/plain

Internal Server Error
```

没有 `code`、没有 `requestId`、没有 `retryable`。前端只能显示一个笼统的失败，且**和后端日志对不上同一次请求**。

原因：网关只把「上游返回 4xx/5xx」翻译成自己的异常类型，而「连不上 / 超时」是 httpx 的网络层异常（`ConnectError` 等），一路穿透到框架默认处理器，框架只会吐上面那行纯文本。

## 二、现在的行为

| 场景 | HTTP | `code` | `retryable` |
| --- | --- | --- | --- |
| 上游没启动 / 端口不通 / DNS 失败 | **502** | `UPSTREAM_ERROR` | `true` |
| 上游连上但不响应（超时） | **504** | `UPSTREAM_TIMEOUT` | `true` |
| 上游返回非 2xx | 502 | `UPSTREAM_ERROR` | `true` |
| 网关自身 bug（兜底） | 500 | `INTERNAL_ERROR` | `false` |
| 入参不合法 | 422 | `VALIDATION_ERROR` | `false` |

响应体统一为：

```json
{
  "code": "UPSTREAM_ERROR",
  "message": "WeKnora 返回错误(502): 无法连接 WeKnora（http://localhost:8080）：请确认上游已启动、地址与端口正确",
  "data": null,
  "retryable": true,
  "requestId": "af5e5d0f0236"
}
```

`X-Request-Id` 响应头与响应体里的 `requestId` 是同一个值。

## 三、对 B 的三点影响

1. **`504` 要处理**：以前所有上游故障都是 502，现在超时单独是 504。如果你的错误文案是 `if (status === 502)` 这种精确匹配，需要放宽到 `502 || 504`。
2. **`retryable` 可以直接驱动「重试」按钮**：502/504 为 `true`，422/500 为 `false`。别再对所有错误都显示重试。
3. **SSE 那条链路行为不变**：流已建立（HTTP 200）后上游挂掉，仍然是一条 `responseType=error` 的事件，字段已齐全：

```json
{"id":"","responseType":"error","content":"无法连接 WeKnora（http://localhost:8080）：…","code":"UPSTREAM_ERROR","retryable":true,"requestId":"c52c1fa32e41","done":true}
```

## 四、验证记录（2026-11-17，A 侧实测）

| 用例 | 手段 | 结果 |
| --- | --- | --- |
| 上游未启动 | 停掉 WeKnora，请求 `/api/v1/knowledge-bases` | 502 + 统一包裹 ✅ |
| 其余端点一致性 | `models` / `documents` / `wiki/tree` / `chunks` 各打一次 | 全部 502 同构 ✅ |
| 超时分支 | `WEKNORA_BASE_URL=http://10.255.255.1:8080`（不可路由）+ 3s 超时 | 504 `UPSTREAM_TIMEOUT` ✅ |
| SSE 错误事件 | 上游停着，`POST /sessions/{sid}/messages` | 事件含 `code`/`retryable`/`requestId` ✅ |
| 兜底处理器 | 进程内注入一个抛 `RuntimeError` 的路由 | 500 `INTERNAL_ERROR` + `requestId` ✅ |

## 五、改动文件

- `gateway/app/weknora_client.py`：网络层异常（`httpx.RequestError`）翻译为 `WeKnoraError`；新增 `WeKnoraError.gateway_status`（超时 504、其余 502）
- `gateway/app/routers/*.py`：15 处错误处理改用 `e.gateway_status`，不再硬编码 502
- `gateway/app/main.py`：新增兜底 `Exception` 处理器，任何漏网异常都走统一包裹

对外字段名、成功响应形状、SSE 事件结构**均未变动**。
