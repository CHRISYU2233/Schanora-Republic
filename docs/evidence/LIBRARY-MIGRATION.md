# 资料库能力迁移报告 · WorkBuddy Library → Schanora

> 日期：2026-11-17 · 执行：B 侧前端（v0.5.3 → 未发版工作区）
> 依据：WorkBuddy 资料库 Skill 文档（`workbuddy-builtin/skills/library`）与 Schanora 现网实现逐项对照。
> 原则：不破坏现有功能、不改网关契约、不在 B 侧伪造服务端能力。

## 一、WorkBuddy 资料库功能清单

| 能力 | 说明 |
|---|---|
| 空间与目录树 | 个人空间 + 团队空间；节点树（文件夹/文档/表格/页面/链接/网盘文件/附件） |
| 资料管理 | 新建/上传/移动/重命名/归档；网页剪藏；附件 |
| 检索 | 全库语义检索（library_search），命中返回片段与来源 |
| 知识库问答 | 基于库内资料的问答，引用来源节点 |
| 分类/标签 | 空间/文件夹组织 + 节点归属 |
| 导入导出 | 上传 md/csv/html/office；导出 doc→md、表格→csv、页面→html；附件 zip |
| 版本历史 | 文档/页面多版本、读历史版本、回滚 |
| 最近访问 | 「继续昨天那份」最近节点 |
| 协作分享 | 评论、协作者权限、邀请链接、页面发布 |

## 三、本轮已实现（迁移落地）

### 1. 文档标签（分类）
- 位置：库内「文档」视图。每行新增「标签」按钮 → 行内编辑（逗号分隔多标签，中英文分号/顿号均可），保存即显示胶囊标签。
- 数据：`localStorage['schanora.doctags.v1'] = { [docId]: string[] }`，单文档上限 12 个，去重保序，规范化（去 `#`、压缩空白、限长 24）。
- 纯函数全部在 `src/lib/tags.js`（normalizeTag / parseTagInput / normalizeTagMap / allTags / filterDocsByTag / mergeTagMaps / serializeTags / parseImportedTags / pushRecent），**9 条单测**（`test/tags.test.mjs`）。

### 2. 标签筛选
- 文档工具栏出现标签 chips（按引用文档数降序）：点击即只显示带该标签的文档，再点取消；无命中给明确空态文案。

### 3. 标签导入 / 导出
- 导出：固定信封 JSON（`{ kind:'schanora.doctags', version:1, exportedAt, tags }`），文件名 `schanora-doctags-<日期>.json`。
- 导入：选文件 → 信封校验（kind/version 不符给中文报错）→ 与现有标签**并集合并**（不覆盖已有），完成后 toast 报合并文档数。

### 4. 最近打开
- 打开文档详情即记录（去重、倒序、封顶 10 条），文档工具栏显示本库最近 3 条，一键回到上次的文档（对齐 WorkBuddy「继续昨天那份」体验）。

## 四、未覆盖项与依赖

| 未覆盖项 | 原因 | 依赖 |
|---|---|---|
| 服务端标签持久化 | 网关无标签端点；B 侧已在界面 title 里如实标注「不随网关同步」 | A 侧新增标签 CRUD 端点后，前端把 localStorage 读写换成 API 即可（纯函数层不变） |
| 库内文件夹/目录树 | 网关文档契约无层级 | A 侧契约扩展 |
| 版本回滚 | 有版本 id 展示、无回滚端点 | A 侧 |
| 评论/分享/权限/发布 | 宿主（DSH）与网关侧职责 | 不迁移 |
| 表格/页面节点 | 产品面不同 | 不迁移 |

## 五、必要配置

- **零新增配置**。不涉及网关、不改设置页、不影响 mock/http 两种模式。
- 存储：浏览器 `localStorage`，键名 `schanora.doctags.v1`、`schanora.recentdocs.v1`。清浏览器数据会丢标签——先「导出标签」可完整找回。
